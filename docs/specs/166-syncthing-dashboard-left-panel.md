## 1. Verified Problem Statement

`SyncthingDashboard` (iframe + status card) is currently rendered inside the
Jobs page (`frontend/src/routes/index.tsx`), above the jobs table. It is not
reachable as its own page, and the sidebar (`Shell.tsx`) has no Syncthing entry.

Desired behaviour:
- When Syncthing is embedded with Docker compose (GUI co-located with the
  backend, not directly browser-reachable on its own port), the sidebar button
  opens an internal route that renders `SyncthingDashboard` (iframe).
- Otherwise (standalone / remote Syncthing), the sidebar button is a plain
  link that opens the Syncthing Web GUI in a new tab.

## 2. Detection decision

Use the backend status already exposed by `GET /api/v1/syncthing/status`:
`gui.reachable === false` means "embedded" (host is `127.0.0.1`).

Rationale:
- In Docker compose, `docker/entrypoint.sh` forces the Syncthing GUI address
  to `127.0.0.1:8384`, and `backend/api/v1/syncthing.py` computes
  `reachable = (SYNCTHING_GUI_HOST != "127.0.0.1")`. So the container reports
  `reachable: false`, which is exactly the "embedded, not browser-reachable"
  case in the issue.
- Standalone/remote deployments set `SYNCTHING_GUI_HOST` to a host the browser
  can reach, so `reachable: true` and the sidebar becomes an external link.
- No backend or config change is required; the flag already exists in both the
  `SyncthingStatus` schema (`shared/schemas/syncthing_status.py`) and the
  frontend `SyncthingStatus` type (`frontend/src/services/types.ts`).

Mock note: `mockService.getSyncthingStatus()` reports `reachable: true`, so in
mock mode the sidebar entry is an external link to `http://127.0.0.1:8384`.
This keeps the mock usable without an iframe route dependency.

## 3. Decisions

### D1 — New route `/syncthing`
File: `frontend/src/routes/syncthing.tsx`. Renders `SyncthingDashboard` inside
`Shell`, mirroring `settings.tsx`. Path chosen to match the `to="/syncthing"`
links used elsewhere.

### D2 — Remove dashboard from Jobs page
Delete the `<SyncthingDashboard />` usage and its import from
`frontend/src/routes/index.tsx`. The Jobs page keeps its metric cards and
table.

### D3 — Sidebar entry in `Shell.tsx`
Add a Syncthing item below the existing `nav` list. Because the target depends
on status, it is rendered separately (not in the static `nav` array):
- Fetch status with `useQuery({ queryKey: ["syncthing","status"],
  queryFn: getSyncthingStatus })`.
- If `data.gui.reachable === false` → `<Link to="/syncthing">` (internal).
- Else if `data.gui.url` present → `<a href={url} target="_blank"
  rel="noopener noreferrer">` (external).
- Otherwise (status not loaded / error) → `<Link to="/syncthing">` (fallback).
Use `Network` from `lucide-react` as the icon and the same className as the
other nav entries so styling matches.

### D4 — Route registration
`routeTree.gen.ts` is generated by the TanStack Router Vite plugin. SWE must
either run `npm run build` (or `vite dev`) to regenerate it after adding
`syncthing.tsx`, or apply the equivalent manual entries. The typecheck gate
(`npm run typecheck`) requires `/syncthing` to be a registered `to` value
before `Link to="/syncthing"` type-checks.

### D5 — No backend changes
No changes to `backend/`, `shared/`, config, or compose. Detection is purely
the existing `gui.reachable` flag.

## 4. Code Shapes

### 4.1 `frontend/src/routes/syncthing.tsx` (new)

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { Shell } from "@/components/layout/Shell";
import { SyncthingDashboard } from "@/components/SyncthingDashboard";

export const Route = createFileRoute("/syncthing")({
  head: () => ({
    meta: [
      { title: "Syncthing · Scientific Home Cluster" },
      {
        name: "description",
        content: "Syncthing sync status and embedded web GUI.",
      },
      { property: "og:title", content: "Syncthing · Scientific Home Cluster" },
    ],
  }),
  component: SyncthingPage,
});

function SyncthingPage() {
  return (
    <Shell title="Syncthing" subtitle="sync status and GUI">
      <SyncthingDashboard />
    </Shell>
  );
}
```

### 4.2 `frontend/src/routes/index.tsx` (modify)
Remove:
```tsx
import { SyncthingDashboard } from "@/components/SyncthingDashboard";
```
and the
```tsx
<SyncthingDashboard />
```
line inside `JobsPage`.

### 4.3 `frontend/src/components/layout/Shell.tsx` (modify)
Add imports:
```tsx
import { useQuery } from "@tanstack/react-query";
import { Network } from "lucide-react"; // alongside existing icons
import { getSyncthingStatus } from "@/services";
```
Inside `Shell`, after `const pathname = ...`:
```tsx
const { data: syncthingStatus } = useQuery({
  queryKey: ["syncthing", "status"],
  queryFn: getSyncthingStatus,
  retry: 1,
});
const syncthingEmbedded = syncthingStatus?.gui?.reachable === false;
const syncthingUrl = syncthingStatus?.gui?.url;
```
After the `nav.map(...)` block in `<nav>`, render:
```tsx
{syncthingEmbedded ? (
  <Link to="/syncthing" onClick={() => setOpen(false)} className={...same...}>
    <Network className="size-4" /> Syncthing
  </Link>
) : syncthingUrl ? (
  <a
    href={syncthingUrl}
    target="_blank"
    rel="noopener noreferrer"
    onClick={() => setOpen(false)}
    className={...same...}
  >
    <Network className="size-4" /> Syncthing
  </a>
) : (
  <Link to="/syncthing" onClick={() => setOpen(false)} className={...same...}>
    <Network className="size-4" /> Syncthing
  </Link>
)}
```

### 4.4 `routeTree.gen.ts`
Regenerate via the TanStack Router plugin (run `npm run build` or `vite dev`).
Manual equivalent: add `SyncthingRoute` import/entry analogous to `SettingsRoute`.
