# Spec: `_resolve_secret_key()` Resilience — Handle Non-UTF-8 Secret File

## Issue
**#67** — `_resolve_secret_key()` crashes with `UnicodeDecodeError` if the persisted `secret_key` file contains non-UTF-8 bytes. The function only catches `OSError`, not `UnicodeDecodeError`.

**Labels**: `bug`, `phase-1`, `ready-for-grooming` → will become `groomed`

---

## 1. Verified Problem Statement

### 1.1 Current Behaviour (Defect)
In `backend/core/config.py:171`, the secret key is read with:

```python
existing = state_path.read_text(encoding="utf-8").strip()
```

If the file exists but contains invalid UTF-8 (e.g., truncated write, manual corruption, or a key generated by a non-compliant tool), `read_text(encoding="utf-8")` raises `UnicodeDecodeError`. The `except OSError:` clause on line 177 does **not** catch it, so the exception propagates out of `_resolve_secret_key()`, crashes Settings construction, and prevents the backend from starting.

### 1.2 Reproduction
```bash
# Create a non-UTF-8 secret_key file
mkdir -p .shc
printf '\xff\xfe\xfd' > .shc/secret_key

# Attempt to import settings (or start the backend)
python -c "from backend.core.config import settings"
# UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0
```

### 1.3 Expected Behaviour
A non-UTF-8 `secret_key` file is treated the same as a missing or published key:
1. The corrupt file is ignored (logged at WARNING level).
2. A new key is generated and persisted **atomically**.
3. The backend starts successfully.

---

## 2. Root Cause

### 2.1 Incomplete Exception Handling
Line 177 catches only `OSError` (file not found, permission denied, etc.). `UnicodeDecodeError` is a subclass of `ValueError`, not `OSError`, so it escapes.

### 2.2 Non-Atomic Write
Line 183 writes the new key with:
```python
state_path.write_text(generated, encoding="utf-8")
```
This is not atomic. If the process is killed mid-write, the file can be left truncated or partially written — creating the very corruption this fix must tolerate.

### 2.3 Secret Leakage Risk in Logs
The function logs `absolute_path` (line 213, 220) but must **never** log the key value itself. The current code does not, but any fix must preserve this invariant.

---

## 3. Scope Boundaries

| In Scope | Out of Scope |
|----------|--------------|
| Catch `UnicodeDecodeError` when reading the secret key file | Change the key format (stays URL-safe base64, UTF-8 decodable) |
| Make the write atomic (temp file + rename) | Rotate keys on a schedule (only on published-key detection) |
| Ensure no secret material appears in logs | Modify `PUBLISHED_KEY_SHA256` or `_digest_secret_key()` |
| Add test coverage for corruption and atomicity | Change `SECRET_KEY` env var behaviour |

## 6. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Atomic write fails on Windows (rename over existing) | Medium | Medium | Use `os.replace()` (atomic on POSIX and Windows since Python 3.3). Test on both. |
| `chmod 0o600` fails on some filesystems (FAT, network mounts) | Low | Low | Wrap `chmod` in `try/except OSError`; log debug, continue. Key in memory is still usable. |
| Corrupt file is a symlink to sensitive location | Low | High | `state_path` is constructed from `_state_dir()` which is either `SHC_STATE_DIR` or `DEFAULT_STATE_DIR` (repo-root-anchored). No user-controlled path component. |
| Log message includes path that reveals deployment structure | Low | Low | Already logs absolute path (line 198). Acceptable — path is not secret. |
| Test flakiness from temp dir cleanup | Low | Medium | Use `tmp_path` fixture; each test gets isolated `.shc` dir. |
| `secrets.token_urlsafe(32)` could theoretically produce non-UTF-8 | None | N/A | `token_urlsafe` returns ASCII (A–Z, a–z, 0–9, -, _), always valid UTF-8. |

## 7. Implementation Approach (for SWE Reference)

### 7.1 Minimal Fix — `backend/core/config.py`

**Change `_resolve_secret_key()` (lines 143–221):**

```python
def _resolve_secret_key() -> str:
    configured = os.environ.get("SECRET_KEY")
    if configured:
        return configured

    state_path = Path(_state_dir()) / "secret_key"
    try:
        # Read with explicit error handling
        raw = state_path.read_bytes()
        existing = raw.decode("utf-8").strip()
        if existing and _digest_secret_key(existing) not in PUBLISHED_KEY_SHA256:
            return existing
        published = bool(existing)
    except (OSError, UnicodeDecodeError) as e:
        if isinstance(e, UnicodeDecodeError):
            logger.warning(
                "The JWT signing key at %s contains invalid UTF-8; "
                "it will be replaced with a newly generated key.",
                state_path,
            )
        published = False

    generated = secrets.token_urlsafe(32)
    try:
        state_path.parent.mkdir(parents=True, exist_ok=True)
        # Atomic write: temp file -> fsync -> rename
        tmp_path = state_path.with_suffix(".tmp")
        tmp_path.write_text(generated, encoding="utf-8")
        tmp_path.chmod(0o600)
        os.replace(tmp_path, state_path)  # atomic on POSIX + Windows
    except OSError:
        logger.warning(
            "Could not persist the generated SECRET_KEY to %s; "
            "tokens will not survive a restart.",
            state_path,
        )
        return generated

    absolute_path = state_path if state_path.is_absolute() else Path.cwd() / state_path

    if published:
        logger.warning(
            "The JWT signing key at %s was published in git history, so anyone "
            "can read it; it has been replaced with a newly generated key. "
            "Previously issued tokens are now invalid - mint a new one with "
            "POST /api/v1/auth/token after setting SHARED_TOKEN (issue #56).",
            absolute_path,
        )
    else:
        logger.info("Generated a new JWT signing key at %s.", absolute_path)
    return generated
```

**Key changes:**
1. `read_bytes()` + explicit `decode("utf-8")` to catch `UnicodeDecodeError` separately.
2. `except (OSError, UnicodeDecodeError)` — both treated as "key absent".
3. Distinct warning for decode failure vs. missing file.
4. Atomic write via `tmp_path` + `os.replace()`.
5. `chmod` on temp file **before** rename (so the final file has correct perms).
6. No secret value in any log message.

### 7.2 Test File — `backend/tests/unit/test_config.py`

Add test class `TestResolveSecretKeyUnicode`:

```python
import pytest
import tempfile
import os
from pathlib import Path
from backend.core.config import _resolve_secret_key, _state_dir


class TestResolveSecretKeyUnicode:
    def test_corrupt_utf8_replaced(self, tmp_path, monkeypatch):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))
        (state_dir / "secret_key").write_bytes(b"\xff\xfe\xfd")

        key = _resolve_secret_key()
        assert len(key) == 43  # token_urlsafe(32) length
        assert (state_dir / "secret_key").read_text() == key

    def test_empty_file_replaced(self, tmp_path, monkeypatch):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))
        (state_dir / "secret_key").write_text("")

        key = _resolve_secret_key()
        assert (state_dir / "secret_key").read_text() == key

    def test_valid_key_reused(self, tmp_path, monkeypatch):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))
        valid = "valid_urlsafe_base64_key_that_is_long_enough"
        (state_dir / "secret_key").write_text(valid)

        k1 = _resolve_secret_key()
        k2 = _resolve_secret_key()
        assert k1 == k2 == valid

    def test_published_key_rotated(self, tmp_path, monkeypatch, caplog):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))
        # Published key from PUBLISHED_KEY_SHA256
        published = "lF8zQJqG_V6AqMI4Fv3REgQA9n5iPXzQn7u6f9G9eVI="
        (state_dir / "secret_key").write_text(published)

        with caplog.at_level(logging.WARNING):
            key = _resolve_secret_key()
        assert key != published
        assert "published in git history" in caplog.text

    def test_atomic_write_no_partial_read(self, tmp_path, monkeypatch):
        """Verify the write is atomic by checking file never contains partial data."""
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))

        # This test validates the implementation pattern, not runtime atomicity
        # (which would require a concurrent reader). We verify the code uses
        # os.replace on a same-filesystem temp file.
        key = _resolve_secret_key()
        content = (state_dir / "secret_key").read_text()
        assert content == key
        assert not (state_dir / "secret_key.tmp").exists()

    def test_no_secret_in_logs(self, tmp_path, monkeypatch, caplog):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))

        with caplog.at_level(logging.DEBUG):
            key = _resolve_secret_key()

        log_text = caplog.text
        assert key not in log_text
        assert "secret" not in log_text.lower() or "secret_key" not in log_text.lower()

    def test_permissions_600(self, tmp_path, monkeypatch):
        state_dir = tmp_path / ".shc"
        state_dir.mkdir()
        monkeypatch.setenv("SHC_STATE_DIR", str(state_dir))

        _resolve_secret_key()
        mode = (state_dir / "secret_key").stat().st_mode & 0o777
        assert mode == 0o600
```
